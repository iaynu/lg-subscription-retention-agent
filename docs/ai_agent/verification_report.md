## 1. 결론

지금까지 만든 것을 실제로 설치·실행해 점검했고, 고객에게 잘못 나갈 수 있던 문제 6건과 동작 오류 10건을 고쳤습니다. 팀이 정한 **알림톡 보고서 형식**과 **DB → Agent 연결**도 구현했습니다. 수정 후 시험 **249건이 모두 통과**합니다(임시 PostgreSQL 16 포함, 점검 전 156건). 서버를 띄워 데모 모드, OpenAI SDK 경로(가짜 서버), 키 없는 모드, DB 모드를 처음부터 끝까지 확인했습니다.

아직 못 한 것은 **실제 OpenAI 호출**(키·모델명 없음)과 **실제 모델 배치 연동**(모델팀 몫)입니다. 문구 품질은 실제 모델로 다시 봐야 합니다.

### 3.3 새로 구현한 것 (팀 결정)

- **알림톡 보고서 형식**: 제목 + 첫 문장 + `▶ 라벨: 값` 0~4줄 + 마무리, 400자. 프롬프트 v3.0, 카탈로그 v1.2(`customer_title`, `message_items`), 검증기 v3, 템플릿. ▶ 값은 고객 공개 값(16종)만 씁니다. 고객 이름은 쓰지 않고 "고객님"입니다.
- **DB → Agent 연결**: `SqlSource`가 예측·구독·고객·제품·문의·방문·사용·결제 테이블에서 입력과 자격 판정 값(카탈로그 조건에 쓰는 사실 27종 중 24종, 나머지 3종은 스키마에 없음)을 계산합니다. 샘플 7건(경로별 1건), 적재 스크립트, 종단 시험 4건.

## 5. 팀 결정이 필요한 것 `[팀 결정 필요]`

1. **OpenAI 모델명**: 지금 `gpt-4o-mini`는 자리표시자입니다. 정해지면 실제 호출로 JSON 유효율·숫자 통과율·폴백 비율·토큰 비용을 잽니다(`agent_validator_design.md` §6.1).
2. **합친 알림톡**: 같은 채널의 솔루션 2개를 한 통으로 합치는 것이 실제 알림톡 템플릿 규정상 가능한지. 지금은 미리보기만 합니다.
3. **협업 부서 매핑**: 카탈로그 `forward_dept` 이름과 부서 8곳의 대응(제 추정), 목업의 T01 협업 예시(카탈로그에 T01 내부 전달 솔루션이 없음).
4. **사건성 3개의 실제 데이터 출처**: 점검 이상(`S-T09-C`)·예상 수리 기간(`S-T10-D`)·매니저 교체 확정(`S-T07-D`) 컬럼은 추가·검증했습니다. 운영에서는 어느 시스템 값을 쓸지 `[팀 결정 필요]`.
5. **설문 보기 공백**: 솔루션 19개가 대응하는 "받은 조치" 보기가 없습니다. "안내·정보를 받음" 보기를 추가할지, `etc`로 둘지.
6. **`S-T05-A` priority 40**: 다른 순수 내부 전달 3건은 10입니다. 일관성 확인.
7. **가정값**: 성수기 시작일, 짧은 케어 기준, `offer_cost` 3건, 비용 상한 비율, 광고 동의율.
8. **만족도 조사(`S-NT-A`)**: 엑셀 밖 항목의 유지 여부와 설문 문구.

## 6. 남은 한계

- 실제 OpenAI 호출을 하지 않았습니다. 가짜 서버로 요청 형식과 오류 경로만 확인했고, 실제 출력에서 검증기의 오탐·미탐이 얼마나 나는지는 모릅니다(특히 키워드로 보는 M4·M8).
- 모델 배치(XGBoost·SHAP)와 연결되지 않았습니다. `SqlSource`는 `churn_prediction`이 채워져 있다는 전제이며 샘플 7건의 예측은 손으로 만든 값입니다.
- 화면은 없고 REST API만 있습니다. 인증·동시성·실제 발송·설문 시뮬레이터는 범위 밖입니다.
- 숫자와 의미의 짝(같은 단위의 다른 값)은 검사하지 못합니다.
- `agent_result.result_json`에 협업 요청서 머리말의 고객 ID·이름이 들어가므로 DB 접근은 내부 직원으로 제한해야 합니다.
