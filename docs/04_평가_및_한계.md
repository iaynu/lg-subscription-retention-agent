# 04. 평가 및 한계 (대표본)

> 정본: `progress_summary.md` · `verification_report.md` · `agent_design.md` §4.7 · `survey_simulator_design.md`
> **먼저 읽을 한 줄**: 데이터가 가설 기반 합성 데이터이므로, 아래 수치는 "시스템이 설계한 구조를 되찾는다"는 **파이프라인 검증**이지 현실 성능이 아닙니다.

---

## 1. 평가를 읽는 방법

정답(라벨·유형)을 만든 규칙을 내가 알고, 모델은 그것을 되찾도록 학습합니다. 즉 검증이 **순환적**입니다. 그래서 이 프로젝트에서 수치는 다음 세 가지 질문에만 답합니다.

1. 단계가 끝까지 이어져 동작하는가
2. 의도한 신호가 모델·유형 도출 단계에서 살아남는가
3. 어디서 약해지는가(약한 유형, 혼동 쌍)

## 2. 예측 모델 (②)

| ROC-AUC | 0.908 | |

위험 등급은 확률 임계값이 아닌 **순위 기반**입니다.

| 등급 | 실제 이탈률 | 전체 이탈자 포착 |

모델 선택: 초기 시뮬레이션에서 XGBoost와 LightGBM의 성능이 같아(PR-AUC 0.420 vs 0.416) **TreeSHAP 호환성**으로 XGBoost를 택했습니다. 성능 우열이 아니라 설명 가능성 기준의 선택입니다.

## 3. 이탈 유형 도출 (SHAP)

유형 도출 규칙: 피처를 유형 그룹으로 묶어 양의 SHAP를 합산 → 비중 20% 이상이고 합 0.5(로그오즈) 이상인 그룹을 최대 3개 채택, 없으면 "유형 없음".

| 지표 (OOF) | 결과 |
|---|---|
| 정답 유형을 하나라도 맞춤 | 97.3% |
| 주 유형 포함 | 93.8% |
| 주 유형이 1순위 | 80.1% |
| 정상 고객 → '유형 없음' | 98.6% |

**약한 지점(숨기지 않고 기록)**
- T04(사용 빈도 저하) 재현율 0.24, T08(영업 압박) 0.49 — 신호가 약하게 설계된 유형
- T09(제품 고장)로 과배정: T05→T09 62건, T06→T09 30건, T10→T09 18건. 고장 관련 피처가 여러 유형에 공통 신호가 되기 때문

## 4. Agent 평가 (③)

### Rule Engine (시뮬레이션, 상위 20% 6,000건)
제안 0개 0.2%, 주 유형 미커버 0.2%, 두 번째 유형 미커버 6.7%, 평균 커버율 90.9%. (초안 대비 두 번째 유형 미커버 60% → 6.7%)

### LLM 문구 (사용자 PC에서 직접 실행한 측정)

| 구성 | 1차 통과 | 사용 가능 | 비고 |
|---|---|---|---|
| nano + 프롬프트 v3.4 + 힌트 가드 | 84% | 95.5% | 부분 템플릿 4.5%, 전체 템플릿 0% |
| mini | 55% | 89% | |

프롬프트 A/B에서 v3.2 85%, v3.3 77%, v3.4 90%로 **개선이 단조롭지 않아** 버전마다 실측했습니다. 가격(1M 토큰): nano $0.20/$1.25, mini $0.75/$4.50.

"사용 가능"은 검증기를 통과했거나 일부만 템플릿으로 대체되어 고객에게 나가도 문제가 없는 비율입니다. 검증기는 문구의 **좋음**이 아니라 **위반 없음**을 확인하므로, 문구의 설득력·자연스러움은 이 수치가 말해 주지 않습니다.

### 구현 점검
설치·실행 점검에서 **고객에게 잘못 나갈 수 있던 문제 6건과 동작 오류 10건**을 찾아 고쳤습니다(예: 광고 동의 값이 없으면 동의로 보던 문제, 확인되지 않은 일을 단정하던 문제, 오류 문자열에 키 조각이 저장되던 문제). 현재 자동 테스트 491건 통과.

## 5. 피드백 루프 (④)

| 항목 | 결과 | 기준선 |
|---|---|---|
| 숨은 주제 H-A 후보 정밀도 | 40~46% | 5.0% |
| 숨은 주제 H-B 후보 정밀도 | 14~24% | 4.3% |
| 재현율 상한 | 약 20% | |

기준선 대비 크게 높지만 **재현율이 낮고 정밀도도 절대적으로는 50% 미만**이라, 이 기능은 "자동 확정"이 아니라 "관리자가 볼 후보 제안"으로만 의미가 있습니다. 통계적 셀 탐지 방식은 거짓 양성이 약 70%여서 폐기했습니다.

## 6. 조치 효과에 대한 가정

조치 후 이탈 확률을 `P_after = P_before × (1 − r)`로 두고, 유형-솔루션 적합도에 따라 r을 0.35~0.55 / 0.10~0.25 / 0~0.05로, 상한 0.7로 두었습니다. 이는 **전부 가정**입니다. 실제 조치 효과는 A/B 테스트 없이는 알 수 없습니다.

## 7. 한계 목록

| 한계 | 영향 | 다음에 한다면 |
|---|---|---|
| 합성 데이터 + 순환 검증 | 현실 일반화 불명 | 실제(또는 비식별 실데이터) 소규모 검증 |
| 이탈 유형 리뷰 근거 편중 (T05 81건 vs T04 3건) | 약한 유형의 정의 신뢰도 낮음 | 상담 로그·해지 사유 코드로 보강 |
| 단일 시점 스냅샷 | 추세·계절성 반영 못 함 | 시계열 피처, 시점별 분할 |
| 조치 효과는 가정값 | ROI 주장 불가 | 처치군/대조군 A/B |
| 검증기 키워드 규칙(M4·M8) | 실제 출력의 오탐·미탐 정도 불명 | 사람 평가 샘플로 보정 |
| 숫자-의미 짝 미검사 | 같은 단위의 다른 값을 쓰면 못 잡음 | 항목별 슬롯 채우기 방식 |
| 화면·인증·실제 발송 범위 밖 | 운영 수준 아님 | 팀 프론트엔드/백엔드와 통합 |
| 설문 응답은 시뮬레이터 | 실제 응답 분포와 다를 수 있음 | 실제 파일럿 설문 |
| LLM 문구 측정은 1회 환경 | 모델 버전 변경에 민감 | 정기 재측정 하네스 |

## 8. 이 프로젝트에서 얻은 판단

- **구조로 안전을 만든다**: LLM 성능을 올리는 것보다, 틀려도 해가 없게 후보 제한·검증·폴백·사람 확인을 겹쳐 두는 쪽이 더 확실했습니다.
- **측정 없이 개선을 믿지 않는다**: 프롬프트 v3.3은 "더 좋을 것 같았지만" 실측에서 떨어졌습니다.
- **약점은 문서에 남긴다**: 유형 복원 약점(T04·T08), 비용 상한이 사실상 작동하지 않는 점 등을 숨기지 않고 후속 과제로 적었습니다.

## 9. 수치 표기 참고

같은 지표가 문서마다 달라 보일 수 있는 부분입니다.

- 전체 이탈률 8.0% = 생성식 시뮬레이션(N=200k) / 8.3% = 실제 생성 데이터(N=30k)
- PR-AUC 0.545 = 고정 시험셋 / 0.573 = 5-겹 OOF
- 솔루션 38건 = 확정 카탈로그 / 33건 = 구독자 단위로 실제 선택 가능(전사 개선 3건·비활성 2건 제외) / 만족도 조사 `S-NT-A` 1건은 별도
